# Quantum acceptance without an IBM subscription

The owner reported that IBM trial access expired and the PAYG upgrade could not be completed. The software release workflow therefore explicitly selects `local-simulator`. It executes the maintained local Bell sampler and analytic ZZ estimator and verifies their actual results and receipts. These are bounded demonstration algorithms, not general circuit simulation or IBM hardware. Existing CPU/exact tests and the independent real Qiskit Aer workflow remain required evidence for their respective paths. Canonical preparation now also waits for a successful exact-main Aer push run; the Aer workflow runs on every main push.

Every live agent, weather, energy, hydrology and transit check remains required, as do all browser/Cesium, exact-main security and engineering checks. Reports retain the selected profile, required and failed provider lists, `ibmVerified: false`, and `hardwareSubmitted: false` / `hardwareExecuted: false`. IBM is recorded as `not-requested`, never as a verified live provider. No cloud job or payment is submitted.

The standalone smoke script defaults to `ibm-required`; `AETHERGRID_ACCEPTANCE_QUANTUM_PROFILE=local-simulator` explicitly selects software acceptance. The protected workflow also offers `ibm-required` when dispatched manually. Once valid IBM account/instance access returns, select that profile to require authenticated backend discovery again. Existing IBM APIs, credentials, adapters and submission safety controls are preserved. See issue #234 for the historical failed discovery evidence.

A successful software-profile workflow certifies this software scope only. It does not restore the expired trial, bypass account restrictions, certify IBM discovery, or establish hardware readiness.
