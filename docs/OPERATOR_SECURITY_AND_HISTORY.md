# Operator accounts and recorded observations

The canonical React console uses the same-origin application server for sessions, role checks, profiles and history. Configure authentication before exposing the runtime to other users. With no accounts configured the application is explicitly a local, single-operator workspace; it is not an authenticated deployment.

Set `AETHERGRID_SETUP_PASSWORD` to a password of at least 12 characters in the local environment, then run `node scripts/configure-aethergrid-account.mjs USERNAME Administrator`. The script writes a salted scrypt hash to the ignored `.env.aethergrid` file and requires authentication. Remove the password environment variable afterward. Add Viewer and Analyst accounts with the same command and their role. Compose reads this file; direct Node startup uses `node --env-file=.env.aethergrid apps/aethergrid-console/server.mjs`. Existing provider settings in the file are preserved. Never commit account configuration.

Sessions expire after eight hours and are revoked by sign-out. Restarting the server revokes every session. Cookies use HttpOnly and SameSite Strict; set `AETHERGRID_PUBLIC_ORIGIN` to the exact HTTPS origin for Secure cookies. Login is limited to eight attempts per minute per connection address; authenticated analysis is limited to 20 requests per minute per user. Viewer may read; Analyst may run advisory analyses and edit their own profile; Administrator additionally controls reset and quantum job routes. Writes require the session CSRF token. Denied requests run no provider tools. Operator audit records contain identity, timestamp, method and path, never request bodies or passwords.

Live weather, environment and city-context responses are recorded only when the upstream contract reports a live source. Archives retain version, location, retrieval time, the sanitized provider payload and a SHA-256 receipt in the persistent data volume. Atomic writes avoid incomplete records; replay validates content hashes. The archive accepts at most 10,000 observations and fails explicitly when full. Back up the data volume and audit file; restore it before starting the runtime. Do not edit observation files.

`GET /api/aethergrid/history?lat=...&lon=...&at=...` returns recorded observations at or before the cursor within six hours. `weather/current`, `environment` and `city-live` accept `at` to replay a recorded response, returning 404 for gaps. Responses disclose the exact saved timestamp and receipt in headers. The historical weather layer uses recorded observations; current mapped buildings remain current topology. Replay never reconstructs unobserved historical infrastructure. Forecasts and scenarios remain separately labeled.

Specialists execute the server's read-only observation tool. Model context includes recorded payloads and citations, not client-supplied citations. TEAM retains individual contribution receipts and deduplicated observation citations. Citation links open the recorded API records. Citations ground the inputs; they do not validate model conclusions. Unconfigured models remain clearly labeled local fallbacks. OpenAI-compatible responses are limited to 1,200 output tokens per request; the existing provider timeout applies. This does not implement infrastructure actuation.

Both Dockerfiles use Minimus Node 22, with dependencies and frontend compilation in the `22-dev` builder and UID 1000 in production. All production commands and health probes use exec form. The `/data` volume is owned by UID 1000. CI builds and starts both containers and checks restart persistence. Optional `docker login reg.mini.dev` increases an account's pull limits; credentials belong only in the runtime/CI credential store.
